01Problem discovery

문제는 정보가 없어서가 아니라, 판단을 맡겨 버리는 데 있었다.

AIP01에서 다섯 문제를 적었다. 국내 연구기관 리포트, 해외 언론·연구소, 거시 변수, 글로벌 기관 리포트, 이 모두를 모아 우선순위를 정하는 오케스트레이터. 그중 문제 1을 먼저 골랐다. 매주 새 보고서가 나오고, 진로·투자·트렌드 판단에 바로 쓰이며, 짧은 기간에 실제로 돌아가는 프로그램을 만들 수 있었기 때문이다.

AIP01 · 처음 생각

보고서가 흩어져 있어 업로드 시점을 놓치고, 긴 PDF를 다 읽을 수 없다.

→ 게시판 수집기 + 쪽수가 붙은 요약 카드 + 공유 페이지

R1 · 재정의

요약이 쌓일수록 스스로 판단하는 비중이 줄어든다. 무엇을 먼저 읽을지, 무엇을 물을지가 내 기준이 아니다.

→ 원문과 해석을 나누고, 질문을 남기고, 내 관심·질문을 순서에 반영

KDI가 성장률을 올렸다는데왜 올렸는지, 한국은행 전망과 무엇이 다른지는 확인하지 않고 지나간다.
두 연구소가 같은 선거를 다르게 읽는다세종연구소와 통일연구원의 중간선거 분석. 어디가 갈리는지 직접 견줘 보지 않는다.
146쪽 지역인구전망요약 한 줄만 읽고 "인구 준다"로 기억한다. 외국인 인구가 지방재정에 주는 영향 같은 질문은 생기지 않는다.

02Issue tree

원인을 세 갈래로 나누고, R1 후반에 "판단을 맡긴다"를 골랐다.

AIP01은 원인 1·2를 풀었다. R1 전반은 원인 2의 읽는 화면을, 후반은 이 프로젝트의 처음 문제의식인 원인 3을 다뤘다. 다만 이 선택은 제작 전에 적어 둔 것이 아니라 돌아보며 정리한 것이다.

ROOT QUESTION

국내 리포트를 업로드 시점에 맞춰 핵심 위주로 익히면서, 내 판단 기준을 키우려면?

03Solution evolution

기능은 늘었지만, 하나는 내렸다.

수집은 코드가(AI 없음), 읽기·정리·쪽수 대조는 Claude가 절차 문서대로 한다. R1 나흘 동안 공유 페이지가 버전 9에서 21까지 바뀌었다. 가장 큰 결정은 만들어 둔 전망 비교표를 상단에서 내린 것이다.

  1. AIP01 · ~11-20수집기 + 카드 + 공유 페이지7기관 16간행물. 수치는 원문 문장과 대조해야만 싣고, 대조에 실패하면 페이지 생성이 멈춘다.
  2. 11-20기관 고르게, 주제와 관련 자료 나누기새 기관이 첫머리에 안 보이는 원인과 주제 필터가 안 갈리는 원인을 찾아 규칙을 바꿨다.
  3. 11-23 · v9~11카드 접기, 읽은 범위 표시, 새 글·검색카드가 3건에서 28건으로 늘자 끝까지 훑기 어려워졌다.
  4. 11-23 · v12전망 비교표 철회 → 섹터별 최신 이슈"0.1%씩 다른 숫자를 매일 상단에 둘 만한가"라는 질문에서, 숫자 비교 대신 흐름 파악으로 무게를 옮겼다. 코드와 원문 대조는 고도화 때를 위해 남겼다.
  5. 11-23 · v13B안 디자인위쪽 골격은 터미널처럼 촘촘하게, 읽는 부분은 종이색과 세리프. 카드 안을 "원문이 말한 것"과 "정리자의 질문"으로 나눴다.
  6. 11-24 · v14~17관심 장부·추적 질문, 반응 버튼, 비공개 노트장기준 6(추적 질문)과 관심 밖 칸을 더하고, 장부는 공개, "내 판단"은 비공개로 나눴다.
  7. 11-24 · v18~21"끝까지 읽음" 표시, GitHub PagesR2 측정을 위한 한 가지 변경. 같은 날 내부 경로가 공개 카드에 섞여 있던 것을 찾아 막았다.

04Hypothesis & test design

R1은 기준 없이 만들었고, R2에서야 기준을 먼저 적었다.

관심 장부와 추적 질문 장부로 고른 "먼저 볼 것"은 끝까지 읽히고, 관심 밖 칸도 함께 읽히며, 그 과정에서 내 질문이 갱신된다.

R2 가설. R1의 가설(내 관심·질문을 기록해 순서에 반영하면 내 기준으로 읽게 된다)은 장치를 만든 뒤에 문장으로 정리했다.

6건 중 3건 이상을 끝까지 읽는다다음 정리 2회의 "먼저 볼 것" 6건. 카드를 다 읽고 원문에서 요약·결론을 직접 확인했을 때만 "끝까지 읽음".
내 기준 자료가 더 읽히되, 관심 밖도 읽힌다기준 5·6 자료의 읽음 비율이 관심 밖 칸보다 높고, 관심 밖 칸도 2건 중 1건 이상.
질문이 갱신된다추적 질문에 기록이 1건 이상 붙거나 새 질문이 1개 이상 생긴다.
가설 유지기준 1과 3을 채운다.
가설 변경기준 1을 못 채운다. 장부가 읽기를 늘리지 못한다는 뜻이므로 원인을 관찰에서 찾는다.
설계내용
측정 장치카드의 "끝까지 읽음" 버튼. 정리할 때마다 직전 "먼저 볼 것"과 대조해 기록한다. 다이제스트가 나온 뒤에 누른 것만 센다.
본인 과업다이제스트가 나온 날부터 다음 다이제스트 전까지 "먼저 볼 것" 3건 중 골라 읽고, 끝까지 읽으면 표시한다.
다른 사용자 과업2명, 1인 10~15분. "카드 하나를 골라 읽고, 앞으로 확인하고 싶은 질문 하나를 적어 주세요." 판정에는 넣지 않고 참고한다.
바꾸지 않는 것R2 동안 "먼저 볼 것" 선정 기준(1~6), 관심 밖 칸, 기관 고르게, 페이지 구성.

05Real voice

들린 목소리는 정리자 한 사람의 것이었다.

사용자 = 만든 사람인 프로젝트였다. 아래는 만들고 쓰는 동안 사용자가 직접 던진 문제 제기와, 그것이 바꾼 것이다. 인용은 원문 그대로다.

11-20 · 노출
기관은 일곱개인데, 첫머리에 노출되는 정보는 기존 기관에 머물러 있는 걸

원인은 버그가 아니라 "노트를 쓴 자료만 싣는" 구조였다 → 기관마다 1건씩 먼저 고르는 규칙.

11-20 · 탐색
주제를 선택했을 때, 확보한 자료들이 충분히 sorting되지는 않는 것 같아

카드 한 장에 태그가 최대 8개였다 → 주된 주제와 관련 주제를 나눴다.

11-23 · 정보 가치
데이터 자체가 0.1%씩 다른 걸 매일 상단노출 시켜둘만큼 중요한 정보인지 의문이야

전망 비교표를 내리고 섹터별 최신 이슈로 바꿨다.

11-21 · 지속 가능성
현재 다루는 문서량이 많다보니 토큰 소모가 우려되네

원문 요점 추출기, 하위 에이전트, 외부 모델 활용을 검토했지만 아직 만들지 않았다.

11-24 · 입력
제대로 된 게 맞나? 입력할 수 있는 창이 딱히 없는데

로그인한 소유자에게만 입력 칸이 보였다. 이후 반응 2건이 저장되어 장부 첫 항목과 추적 질문 Q1이 생겼다.

11-24 · 방향
지나치게 사용자 스스로의 생각 정리용 및 정보 수집을 위한 용도라는 목적이 강해

다른 사람이 쓰는 상호작용형 도구로의 재조정을 검토하기 시작했다(08 결정).

가장 큰 빈칸: 다른 사용자 검증 0명

AIP02의 "사용자 2명 이상에게 시험"을 R1에서 하지 않았다. R2 계획에 과업 안내문과 관찰표를 만들어 두었지만 아직 보내지 않았다.

07Current version & concerns

지금 할 수 있는 것과, 할 수 없는 것.

할 수 있는 것
  • 7기관 16간행물 게시판의 새 글 수집(robots.txt 준수)
  • 수치마다 원문 문장·쪽수 대조, 읽은 범위 표시
  • "먼저 볼 것"(기준 1~6, 관심 밖 칸)과 섹터별 이슈
  • 공유 페이지: 필터·검색·새 글·장부·정리자 반응
  • 반응·노트장·대화로 받은 입력을 장부 변경안으로
아직 못 하는 것 · 만들면 됨
  • 무인 실행(지금은 사람이 정리를 시작해야 함)
  • 목록 2쪽 이후 확인, 막힌 기관 수동 등록
  • 토큰 절감 장치(요점 추출기, 하위 에이전트)
  • 방문 통계, 다른 사람의 반응 모으기
할 수 없는 것 · 외부 제약
  • robots.txt가 막은 기관의 자동 수집(KCIF, KIEP 등)
  • 한국은행 원문 PDF 자동 수집
  • claude.ai 공유 페이지에서 다른 계정 방문자의 입력
고민지금 상태
누구를 위한 것인가정리자 한 사람의 생각 정리와 정보 수집에 치우쳐 있다. 다른 사람이 언제, 왜 여는지가 비어 있다.
GPT와 무엇이 다른가국내 기관 원문과 쪽수 대조라는 신뢰 장치는 강하다. 그러나 "물어보면 바로 답한다"는 편의는 GPT가 앞선다.
지속 가능한가정리할 때마다 원문 읽기에 토큰이 많이 들고, 실행을 잊으면 수집도 멈춘다.
얼마나 공개할 것인가장부·반응은 공개, "내 판단"과 노트장은 비공개. 한국은행 이용 조건 때문에 GitHub판은 검색 색인을 막았다.

08Decision & next step

R2는 보류하고, 사용자를 바꾸는 재조정을 검토한다.

R2(같은 가설 추가 검증)를 시작해 1회차 정리까지 마쳤다. 그러나 다른 수강생의 R1 보고를 보며 "내가 만든 것은 다른 사람이 쓰는 순간이 없다"는 점이 분명해졌다. R2와 R3는 재검토한 뒤 진행하기로 하고, 그동안 읽음 기록은 계속 쌓는다.

지금 · 정리자용 브리핑

카드 목록에서 시작한다

새 보고서 요약 → 먼저 볼 것 → 정리자의 질문. 상호작용은 소유자 전용.

재조정안 · 시사·경제 면접 준비생

예측에서 시작한다

면접에서 "왜 그렇게 보나요?"라는 물음에 근거를 대지 못하는 20대를 위해, 원문을 보기 전에 먼저 예측하고 원문 근거를 골라 내 입장을 쓰게 한다.

  1. 주제 고르기: 면접에 나올 만한 이슈(성장과 소비, 원화와 물가, 북미 협상, 인구와 지방재정)
  2. 먼저 예측하기: "KDI는 내년 성장률을 올렸을까, 내렸을까?"
  3. 원문 확인: 정답을 원문 문장과 쪽수로 공개, 맞힌 것과 틀린 것 표시
  4. 다른 시각: 같은 사안을 다르게 본 기관을 나란히
  5. 내 입장 한 줄: 원문 근거를 하나 골라야 저장된다
  6. 예상 질문과 30초 답변 틀: 주장 → 근거(쪽수) → 한계
검증 설계 (제안값, 확정 전)

시사·경제 면접 준비생 3명, 1인 15분. 같은 질문에 사용 전과 사용 후 30초씩 답하게 하고, 답변에 원문 근거가 늘었는지 본다. 예측 단계를 건너뛰거나 "GPT가 더 빠르다"가 주된 반응이면 재검토 신호로 본다.

재검토 때 정할 것
  1. 어떤 직무·기업의 면접을 상정할지
  2. 시험할 3명을 어디서 구할지
  3. 판단 기준을 제안값대로 쓸지
  4. 한국은행 자료를 넣을지
  5. R2를 이어갈지 중단할지, R3를 이 안으로 시작할지
Conclusion

믿을 수 있게 모으는 것은 했다.
다음은 다른 사람이 쓰는 순간을 만드는 것이다.

원문 쪽수와 대조한 요약, 원문과 해석의 분리, 스스로 따져볼 질문은 이 프로그램의 자산이다. 다만 지금은 그 자산을 정리자 한 사람만 쓴다. 다음 라운드에서는 이 자산을 다른 사람의 판단 연습으로 옮길 수 있는지 확인한다.
